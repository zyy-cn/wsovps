# Operating Constitution

- Canonical deployment flow remains the same as the base kit; this kit only strengthens runtime governance.
- The researcher and web-side GPT decide; Codex executes bounded tickets.
- Local code is the mutable source of truth; remote runners are execution mirrors.
- Derived views are helpers only; canonical docs and executable truth win on conflict.
- Takeover is the primary web-side review package; latest review packet is the standard per-run companion for web-side GPT review.
- Long-running infrastructure is opt-in and must follow the managed launch path.
- Experiment management is gate-first, lightweight, and mini-safe. Parallel experimentation is allowed, but governing truth remains single-writer.
- Experiment registry, indexes, and takeover experiment ledgers are tool-managed only.
- Gate-boundary git is allowed; routine iterations default to commit-tree sync or ssh snapshot sync as permitted by policy. Only a designated synthesis step may promote branch-local outcomes into canonical current-state truth.
- Module-gated development must use an approved Design Pack before code changes when protocol semantics, data semantics, evaluation semantics, or shared paths are affected.
- Settled gates do not auto-promote the next gate. They wait for the next planning turn.

## Commit and delivery discipline
- Every code-changing run must bind to a local git commit and a clean working tree unless the ticket explicitly records justified dirty-state handling.
- Runtime-only overrides must still be captured by a config snapshot.
- Delivery mode is explicit per ticket and may require a design pack.
- Shared-path edits require an explicit backward-compatibility note and a bounded validation plan.
- Tiny smoke evidence is mandatory before larger execution for module-oriented engineering work.
